# 캐릭터·펫 동작 점검 — 2026-09-10

이 문서는 기존 납품 성능·오프라인 검사와 별개인 동작 수정 기록이다. 앱 전체 빌드는 루트 담당자가 통합 시 실행한다.

## 확인한 원인

- 기존 4종 캐릭터의 `attack_0/attack_1`에는 영문 키캡이 그림에 포함돼 있었다. 예: `char_brown_boy.webp`의 `attack_0`은 `(810,445,222,206)`, `attack_1`은 `(376,445,224,210)`이다. 한국어 입력일 때 원본 공격 그림을 재생하면 영문이 보이는 것은 UI 번역 문제가 아니다.
- 기존 오른쪽 걷기 4프레임은 비슷한 접지 자세에 몰려 있다. 특히 고양이·용·다람쥐는 자세 차이가 작고 토끼는 공중 자세가 반복돼, 타이밍만 바꿔서는 충분한 보폭 교대를 만들 수 없다.
- 프레임에 이미 있는 몸 높이 변화에 별도 사인파 상하 움직임이 겹쳤다. 원본 atlas의 source height와 실제 trim bottom에도 차이가 있어 발선이 달라졌다.
- 짧은 타이핑 동작 직후 단어를 완성하면 `busy` 때문에 완성 공격을 생략하던 경로가 있었다. 피격을 빠르게 반복하면 Enemy의 여러 이동·기울기·색상 타이머가 동시에 남았다.

## 적용한 동작 계약

- Player와 Pet의 좌우 이동은 `char_walk_v1` / `pet_walk_v1`의 행별 4프레임을 사용한다. 왼쪽은 오른쪽을 반전한다. 정면·뒷면과 새 atlas가 없는 환경은 원본 프레임을 유지한다.
- 걷기 7fps, 달리기 10fps에서 속도 보정은 `timeScale`만 바꾸므로 도중에 보폭이 초기화되지 않는다. 달리는 동안 타이핑·피격·펫 축하가 걷기 애니메이션을 정지시키지 않는다.
- 한국어 공격은 `char_attack_ko_v1`의 행별 4프레임, 영어는 원본 영문 공격을 사용한다. 종료하면 선택 캐릭터의 원본 sheet·크기·방향으로 복귀한다.
- 새 atlas의 `customData.bodyHeight`로 원본 캐릭터 높이에 맞추고 `customData.foot`로 발선을 맞춘다. Phaser의 JSON metadata 중첩 구조를 명시적으로 처리한다.
- 장면이 관리하는 `sprite.x/y`와 입력 피드백을 분리했다. 공격과 가벼운 몸 이동은 표시 원점만 바꾸므로 도중에 장면이 위치를 바꿔도 오래된 좌표로 되돌리지 않는다.
- 승리 자세는 서로 다른 포즈를 무한 교차하지 않고 유지한다. 캐릭터는 한 번만 작게 뛰고, 펫은 스킬 색상을 남기지 않는다.
- Enemy 약한 피격은 18px/85ms, 강한 피격은 40px/110ms 왕복 한 번이다. 새 동작이 기존 이동·기울기·색상 타이머를 정리한다. 쓰러진 뒤 오래된 공격 callback이 발생하지 않는다.
- 움직임 줄이기에서는 추가 상하 이동, 넉백, 기울기, 승리 점프를 사용하지 않는다. 필수 보행 프레임과 입력 동작은 계속 읽을 수 있다.
