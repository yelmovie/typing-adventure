# 게임플레이·저장 독립 QA — 2026-09-10

검사 환경: 실제 Chrome의 격리된 Playwright 컨텍스트, 개발 서버 `http://127.0.0.1:5180`, 1280×800, 동작 줄이기. 테스트 전용 저장 자료를 사용했고 사용자의 브라우저 기록은 변경하지 않았다. 병렬 개발의 HMR 새로고침은 차단했다. 이 검사는 소스 수정·제품 빌드 없이 수행했다.

| 검사 | 실제 절차와 결과 | 판정 |
|---|---|---|
| 튜토리얼 입력 | 한국어 목표를 입력하고 Enter로 제출했다. 미리 채워진 `젤러`에서 End → Backspace → `리`로 `젤리`를 만들었고, NFD 문자열도 NFC 정답으로 처리됐다. | PASS |
| 조합 중 Enter | 입력 칸에 합성 `compositionstart`를 보낸 뒤 Enter를 눌러 다음 단계가 열리지 않음을 확인했다. `compositionend` 뒤 Enter로 정상 제출됐다. | PASS — 합성 이벤트 범위 |
| 언어별 완료 기록 | KO 튜토리얼 완료 → 홈의 English 버튼 → EN 미완료 상태 확인 → EN 첫 단계만 수행하고 나가기 → 한국어 버튼으로 복귀 → 새로고침. KO 완료는 유지됐고 EN은 미완료였다. | PASS |
| 중간 나가기 | 홈에서 연 EN 튜토리얼을 중간에 나가면 홈으로 돌아왔고 완료로 저장되지 않았다. | PASS |
| 새 모험 | KO 완료 상태에서 홈의 새 모험 시작 → 확인 → 준비 화면의 세 단계 완료. 새 KO 모험의 완료 표시는 초기화되고 EN 이름·아카이브는 유지됐다. 첫 KO 튜토리얼이 다시 열렸으며 나가기 후 지도에 도착해도 완료는 `false`였다. | PASS |
| 예전 고스트 교체 | 같은 브라우저의 실제 앱 모듈에서 결과 저장을 호출했다. 메타데이터 없는 1000m·20초 기록에 500m·규칙 v2·65초 완주 결과를 저장하자 새 기록으로 교체됐다. 기존 기록이 더 짧아도 다른 코스와 비교하지 않았다. | PASS |
| 같은 규칙의 최고 고스트 | 이어서 500m·v2·70초 결과를 저장하자 65초 최고 기록이 유지됐다. 새로고침 후 `goalDistance: 500`, `rulesVersion: 2`도 보존됐다. | PASS |

검사 중 브라우저 실행 예외는 없었다. 고스트 검사는 완주 결과 자료를 주입해 **실제 저장 경로**를 확인한 것이며, 65초 동안 실제 키보드로 레이스를 완주한 검사는 아니다.

## 발견 사항 — 수정 및 회귀 확인

튜토리얼 마지막 단계에서 **첫 정답 → 오답 Enter → 두 번째 정답**을 수행해도 “두 번 연속 성공!”이 표시되는 불일치를 발견했다. root가 오답 제출 시 두 낱말 콤보를 첫 낱말부터 다시 시작하도록 수정했다. `scripts/check-tutorial.ts`의 실제 연속 조건 검사와 `scripts/check-tutorial-flow.mjs`의 첫 정답→오답→첫 낱말 복귀→다시 두 정답 브라우저 회귀를 추가해 확인했다. 코인·학습 성취 수치는 연습으로 지급하지 않는다.

## 미검증 범위

- Windows 실제 한글 IME의 물리 키 입력·조합 이벤트 순서: **NT**. 합성 composition 검사와 NFD 입력 성공을 실제 OS IME 검증으로 해석하지 않는다.
- 실제 학생 사용성·교육 효과, 실교실 장비·망: **NT**.
- 튜토리얼 완료 상태는 현재 언어의 모험 진행에 속한다. 새 모험에서 다시 안내되는 동작을 확인했으며, 모든 언어·새 모험을 통틀어 영구히 한 번만 안내하는 정책은 구현·검증 범위가 아니다.
