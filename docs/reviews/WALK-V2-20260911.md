# 네 캐릭터 보행 및 옆모습 런타임 검수 — 2026-09-11

## 바뀐 동작

- 하늘·보라·지호·루카의 좌우 이동은 `char_walk_v2`의 각 행 `c0`~`c7`을 사용한다. 왼쪽 이동은 같은 그림을 반전한다. 옆을 보고 멈출 때는 같은 모델의 중립 포즈 `c8`을 써서, 지호의 안경이 사라지거나 걷던 캐릭터가 다른 옆모습으로 바뀌지 않는다.
- 이동을 유지하는 `idle()` 요청이 먼저 원본 시트로 바꾸던 순서를 고쳤다. 동일 애니메이션을 다시 재생하지 않는 Phaser 옵션과 원본 텍스처 변경이 충돌하던 순간적인 그림 전환을 없앴다.
- 걷기와 달리기는 같은 애니메이션을 공유하고 재생 속도만 바꾼다. 방향·속도 변화가 첫 프레임으로 되돌아가지 않으며, 웅크리기와 점프 뒤에는 중단했던 보행 프레임으로 돌아온다.
- 비슷한 최대 보폭 포즈가 연이어 나오는 `c3→c4`, `c7→c0`의 체류 시간을 줄였다. 각 프레임 실제 시간은 **75, 100, 100, 25, 75, 100, 100, 25 ms**이며 기본 달리기 한 주기는 **600 ms**다. 느린 걷기는 같은 주기의 0.75배 속도다. 별도 상하 진동을 보행에 더하지 않는다.
- 1단계에서는 실제 발밑 길이 그려진 배경을 설계 좌표 기준 **120 px/s**로 이동한다. 입력판 뒤에 가려지는 아래 장식 줄만 빠르게 움직이던 주석과 속도 연결을 바로잡았다.
- 2단계에서는 도로와 플레이어가 같은 속도 범위(기본의 0.75~1.35배)를 사용한다. 도로 속도는 **90~162 px/s**다. 고스트의 상대 거리 계산은 그대로이며, 고스트도 새 보행 시트와 발 기준점을 사용한다.
- 원본 프레임, 그림자, 게임 기록, 점수와 타이핑 판정은 삭제하거나 초기화하지 않았다.

## 확인한 범위

### 엔티티 회귀

`scripts/check-entity-motion.mjs`를 격리한 Chrome/Phaser 장면에서 실행했다.

- 최종 결과: **96/96 통과** — 일반 모션과 OS 모션 줄이기 각각 48항목.
- 4명 좌우 8프레임, 정지 시 같은 옆모습, 속도·방향 전환 시 프레임과 경과 시간 유지, 웅크리기 복귀를 확인했다.
- 타이핑·피격 때 플레이어와 펫의 루프 유지, 점프/웅크리기 착지, 액션 콜백 1회 호출, 종료 후 콜백 해제, 승리 포즈와 효과 복구를 확인했다.
- 그림 위치를 실제 장면에서 변경한 뒤에도 짧은 타격 효과가 원래 위치로 되돌리지 않는지 확인했다.
- 기본 달리기의 `c0→c0` 주기를 실제 Phaser 이벤트 시간으로 측정했다. 일반 **599.7 ms**, 모션 줄이기 **599.6 ms**였다. 초기 조정 중 발견한 Phaser `frame.duration` 의미 차이는 최종 값으로 수정한 뒤 다시 검사했다.
- 증거: `tmp/entity-motion-20260911-cadence/results.json`.

### 실제 1·2단계 연결

`scripts/check-stride-scenes.mjs`는 각 캐릭터마다 독립 저장소를 사용하는 브라우저를 열어 실제 인트로·필수 연습·전투 입력을 거친다. 개발용 모듈 함수를 호출해 연습을 건너뛰지 않는다.

- 1단계 자음 19개 / 2단계 모음 21개를 실제 입력창과 Enter로 완료한 뒤 전투에 들어간다.
- `ensureScreenAssets`가 새 WebP/JSON 두 파일을 실제로 HTTP 200으로 받는지 확인한다.
- 인트로에서 `c8` 정지 포즈로 멈추는지, 전투에서 3낱말을 연속 입력하는 동안 8프레임이 순환하며 재생 시작 이벤트가 다시 발생하지 않는지 확인한다.
- 펫의 이동 루프, 플레이어/그림자 위치, 발 기준점의 오차(타이핑 피드백 2 px 이내), 실제 도로 이동 속도를 함께 측정한다. 도로는 Phaser의 시뮬레이션 시간에 대해 측정하여 테스트 PC의 일시적인 벽시계 지연과 구별한다.
- 최종 8개 장면 결과: **8/8 통과** — 하늘·보라·지호·루카 × 1·2단계.
- 증거: `tmp/stride-scenes-20260911-cadence/results.json`, 같은 폴더의 캐릭터·스테이지별 PNG.
- 도로 속도 측정을 시뮬레이션 시간 기준으로 보강한 추가 루카 1·2단계 검사도 **2/2 통과**했다. 증거: `tmp/stride-scenes-20260911-delta/results.json`.

## 해석의 한계

최종 production 확인: `dist-preview-20260911-walk-v2-final/`을 4176에서 실행하고 실제 홈→지도→지역→필수연습→전투 버튼 경로로 지호 1단계·루카 2단계를 확인했다(2/2). 개발용 window.__game 없이 새 v2 WebP/JSON HTTP200, 실제 정답 입력, 브라우저 오류 없음을 확인하고 화면을 직접 검토했다. 증거 `tmp/walk-preview-final/results.json` 및 같은 폴더 PNG. manifest `9398de451eb9db33`의 429자산 크기·SHA가 모두 일치했다. `npm run check`, `npm run typecheck`, 최종 production build도 통과했다.

자산 검수: 320px 셀에서 머리 중심 좌우 오차는 인물별 1px 미만, 모든 발 기준선은294px, 대기 이미지 bodyHeight는240px다. 지호의8보행+1대기 자세에 안경을 확인했고 보라 외곽 잡점이 큰 군집으로 남은 첫 결과는 이미지 생성 수정 후 교체했다. 매우 작은 윤곽 잔점은 검정 배경에서 일부 남지만 실제 장면에서는 큰 배경색 테두리나 의상 내부의 구멍이 보이지 않았다. 내장 image_gen 원본5장·최종프롬프트는 `docs/media/CHARACTER-WALK-V2-PROMPTS.md`에 기록했다.

자동 검사는 연결, 반복 재생, 타이밍과 위치 안정성을 확인한다. 학생이 느끼는 자연스러움이나 재미를 점수로 인증하지 않는다. 접촉 포즈가 일부 비슷한 생성 이미지의 특성을 체류 시간으로 보완했으며, 발바닥마다 물리 엔진으로 접지를 계산하는 방식은 아니다.

입력은 실제 DOM 이벤트로 검증했지만 운영체제 한글 IME와 학교 기기 실물 검사는 이번 범위에 포함하지 않았다. 원본 생성·배경 제거·패킹에 관한 출처와 세부 검수는 별도 미디어 문서를 따른다. 이 보고서는 최종 코드의 보행 동작에 한정한다.
