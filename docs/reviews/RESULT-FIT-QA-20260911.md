2026-09-11. 소스 개발 서버 `http://127.0.0.1:5180`에서 `scripts/check-result-fit.mjs`를 실행했다. 기존 사용자 브라우저와 분리된 Playwright 컨텍스트를 사용했고 개인 저장 기록은 건드리지 않았다.

## 검사 방법

- 실제 소스 `navigate`로 해당 스테이지 소개 화면을 먼저 열어 배경과 캐릭터 자료를 준비한 뒤 실제 `ResultScreen`과 `ResultScene`을 열었다. 합성 결과는 화면의 많은 보상·긴 기록을 검사하기 위한 것으로 실제 점수나 보상 산식 검증이 아니다.
- 한국어·영어 × 입력 0회 실패 / 많은 보상과 성장 기록 / 5단계 최종 완료 × 1280×800·1024×768·915×412·1920×1080, **24개 사례**다.
- 많은 보상 사례는 배지 16개, 새 친구 3명, 칭호 3개 등을 넣었다. 작은 화면에서 선물 목록이 최대 20페이지로 나뉜다. 탭이나 화면 크기를 바꿔도 현재 페이지가 유지되므로 실제 이전 버튼으로 첫 페이지에 돌아간 뒤 마지막 페이지까지 검사했다.
- `이번 결과 / 성장 기록 / 받은 선물`의 세 탭, 본문·각 페이지·각 카드에 가로·세로 스크롤이 필요하지 않은지 확인했다. 텍스트의 실제 줄 영역을 측정해 `overflow:hidden` 등으로 잘린 경우도 실패 처리한다. 카드가 페이지 이동 버튼 영역을 침범하지 않는지도 검사했다.
- 메인 버튼과 페이지 버튼이 다른 요소에 가리지 않고 실제 클릭 가능한지 확인했다. 실제 Phaser 지호·아기 드래곤의 프레임 경계와 결과 패널이 겹치지 않는지 검사했다. 이번 자동 치수 검사는 이 캐릭터·펫 조합이며 모든 캐릭터 조합을 실행한 것은 아니다.
